    Быстрое преобразование Фурье (FFT)¶

    Уровень: продвинутый · Время чтения: 40 минут · Теги: fft, math · Проверил: —

    Что нужно знать заранее

    • Массивы, функции, рекурсия и смысл \(O(n)\), \(O(n^2)\), \(O(n\log n)\).
    • Как раскрывать скобки: \((1+2x)(3+4x)=3+10x+8x^2\).
    • Комплексные числа и корни из единицы объясним здесь. Матрицы и математический анализ не понадобятся.
    • Для последнего упражнения пригодятся префиксные суммы.

    Что в статье

    1. Почему многочлены удобно умножать через значения в точках.
    2. Откуда берутся комплексные корни из единицы и как FFT считает все значения сразу.
    3. Как вернуться к коэффициентам и написать прямое и обратное преобразование.
    4. Задача 1. Умножение многочленов — весь алгоритм на одном примере.
    5. Задача 2. Яблоки и бананы — сколько пар дают каждую возможную сумму.
    6. Задача 3. Пары единиц — простое условие, за которым прячется свёртка.
    7. Задача 4. Подотрезки — упражнение: соединяем свёртку с префиксными суммами.

    Зачем это нужно¶

    В олимпиадных задачах часто нужно перемножать многочлены: их коэффициенты могут хранить количество способов набрать сумму или значения динамики. При обычном раскрытии скобок каждый коэффициент первого многочлена умножается на каждый коэффициент второго.

    Для двух массивов по \(65\,536\) коэффициентов это \(65\,536^2=4\,294\,967\,296\) произведений. FFT заменяет их тремя преобразованиями длины \(131\,072\), по 17 уровней каждое, и одним проходом для поэлементного умножения. Это задача 1. Затем увидим, как к тому же действию сводятся задачи про фрукты и бинарные строки.

    Идея¶

    Многочлен — сумма чисел, умноженных на степени \(x\). Например, \(A(x)=1+2x\) хранится как массив [1, 2]: сначала коэффициент при \(x^0=1\), затем при \(x^1\).

    Перемножим \(A(x)=1+2x\) и \(B(x)=3+4x\):

    \(\times\) \(3\) \(4x\)
    \(1\) \(3\) \(4x\)
    \(2x\) \(6x\) \(8x^2\)

    Складываем слагаемые с одинаковой степенью. Получается \(C(x)=3+10x+8x^2\), то есть массив [3, 10, 8]. Такая операция над массивами называется свёрткой.

    Теперь посмотрим на тот же многочлен иначе: не на его коэффициенты, а на значения в выбранных точках.

    Точка \(z\) \(A(z)\) \(B(z)\) \(C(z)=A(z)B(z)\)
    0 1 3 3
    1 3 7 21
    2 5 11 55

    В каждой строке ответ получается одним умножением: значение произведения равно произведению значений. Смешивать коэффициенты уже не надо.

    План: перейти от коэффициентов к значениям, перемножить значения попарно, восстановить коэффициенты. Если каждый переход быстрый, всё умножение тоже быстрое.

    Но обычная подстановка во все точки снова потребовала бы квадратного времени. Весь секрет — выбрать точки так, чтобы вычисления можно было переиспользовать.

    Алгоритм¶

    Сколько коэффициентов и точек нужно¶

    Если в \(A\) лежит \(n\) коэффициентов, его степень не больше \(n-1\). Если в \(B\) — \(m\), степень произведения не больше \(n+m-2\). Значит, ответ содержит \(n+m-1\) коэффициентов.

    В нашем примере \(n=m=2\), поэтому нужно три коэффициента. Четвёртый можно считать нулём: [3, 10, 8, 0] — тот же многочлен.

    Многочлен степени меньше \(N\) однозначно задаётся значениями в \(N\) различных точках. С коэффициентами получаем одно описание, со значениями — другое описание того же объекта.

    Почему значения определяют многочлен

    Допустим, два разных многочлена степени меньше \(N\) совпали в \(N\) различных точках. Их разность — ненулевой многочлен степени меньше \(N\) с \(N\) корнями. Такого быть не может: ненулевой многочлен степени \(d\) имеет не больше \(d\) различных корней. Значит, эти два многочлена на самом деле одинаковые.

    Выбираем \(N\) — степень двойки, не меньшую \(n+m-1\), и дописываем в оба массива нули до длины \(N\). Почему степень двойки — скоро увидим: FFT будет делить задачу пополам.

    Здесь \(n+m-1=3\), ближайшая подходящая степень двойки — 4. Работаем с [1, 2, 0, 0] и [3, 4, 0, 0].

    Комплексные числа: достаточно поворотов¶

    У обычных чисел квадрат не бывает отрицательным. В комплексных числах есть число \(i\), для которого \(i^2=-1\).

    Число \(a+bi\) можно представить точкой: \(a\) — координата по горизонтали, \(b\) — по вертикали. Например, \(1+2i\) — точка \((1,2)\).

    Складываем отдельно обычные части и части с \(i\). Умножаем как скобки, заменяя \(i^2\) на \(-1\):

    \[ (1+2i)(3+4i)=3+4i+6i+8i^2=-5+10i. \]

    Умножение на \(i\) поворачивает точку на четверть оборота против часовой стрелки:

    \[ 1\ \longrightarrow\ i\ \longrightarrow\ -1\ \longrightarrow\ -i\ \longrightarrow\ 1. \]

    Умножение на число \(\cos\alpha+i\sin\alpha\) так же поворачивает точку на угол \(\alpha\), не меняя её расстояния до нуля. Только это свойство комплексного умножения нам и потребуется.

    Корни из единицы¶

    Числа \(1,i,-1,-i\) после возведения в четвёртую степень дают 1. Их называют корнями четвёртой степени из единицы: это решения уравнения \(z^4=1\).

    Для общего \(N\) берём поворот на \(1/N\) полного круга:

    \[ \omega=\cos\frac{2\pi}{N}+i\sin\frac{2\pi}{N}. \]

    Полный круг — \(360^\circ\), или \(2\pi\) радиан. При \(N=4\) угол равен \(90^\circ\), поэтому \(\omega=i\).

    Точки \(1,\omega,\omega^2,\ldots,\omega^{N-1}\) равномерно стоят на окружности радиуса 1. Каждый новый множитель \(\omega\) делает ещё один шаг по кругу, а после \(N\) шагов возвращает нас в 1: \(\omega^N=1\).

    DFT, дискретное преобразование Фурье, — массив значений многочлена в этих точках:

    \[ y_k=A(\omega^k),\qquad k=0,1,\ldots,N-1. \]

    FFT, быстрое преобразование Фурье, — алгоритм, который вычисляет DFT за \(O(N\log N)\). DFT обозначает, что вычисляем, FFT — как это делаем.

    Делим коэффициенты на чётные и нечётные¶

    Разделим многочлен по индексам коэффициентов. Например,

    \[ A(x)=1+2x+3x^2+4x^3 =\underbrace{(1+3x^2)}_{\text{чётные степени}} +x\underbrace{(2+4x^2)}_{\text{нечётные степени}}. \]

    Введём два многочлена вдвое короче: \(E(t)=1+3t\) и \(O(t)=2+4t\). Тогда

    \[ A(x)=E(x^2)+xO(x^2). \]

    В общем случае \(E\) хранит [a₀, a₂, a₄, …], а \(O\) — [a₁, a₃, a₅, …]. Делим не массив на левую и правую половины, а берём элементы через один.

    Подставим две противоположные точки \(z\) и \(-z\):

    \[ A(z)=E(z^2)+zO(z^2),\qquad A(-z)=E(z^2)-zO(z^2). \]

    Квадрат у них одинаковый. Поэтому одни и те же значения \(E(z^2)\) и \(O(z^2)\) дают сразу два ответа.

    Почему подзадачи тоже FFT¶

    Для четырёх точек это видно руками:

    Исходная точка \(1\) \(i\) \(-1\) \(-i\)
    Её квадрат \(1\) \(-1\) \(1\) \(-1\)

    Четыре точки после возведения в квадрат превратились в две различные точки. Причём это корни уже второй степени из единицы.

    Для любого чётного \(N\) происходит то же самое: противоположные точки сливаются, и остаются \(N/2\) корней степени \(N/2\).

    Значит, можем рекурсивно вычислить FFT для \(E\) и \(O\), а потом склеить результаты. Если бы мы подставляли произвольные точки, такого уменьшения их количества могло бы не быть.

    Склейка: одна пара — два ответа¶

    Пусть рекурсия вернула:

    • \(u_k=E(\omega^{2k})\);
    • \(v_k=O(\omega^{2k})\).

    Для \(k=0,\ldots,N/2-1\) положим \(t=\omega^k v_k\). Тогда:

    \[ \boxed{y_k=u_k+t,\qquad y_{k+N/2}=u_k-t.} \]

    Вторая точка — противоположная первой: \(\omega^{k+N/2}=-\omega^k\). Такую склейку часто называют бабочкой: два входа расходятся в два выхода.

    На \(A=[1,2,0,0]\) получаем \(E=[1,0]\), \(O=[2,0]\). Их FFT — [1, 1] и [2, 2]:

    \(k\) \(\omega^k\) \(u_k\) \(v_k\) \(y_k=u_k+\omega^kv_k\) \(y_{k+2}=u_k-\omega^kv_k\)
    0 1 1 2 \(3\) \(-1\)
    1 \(i\) 1 2 \(1+2i\) \(1-2i\)

    Итак, FFT от [1, 2, 0, 0] — [3, 1+2i, -1, 1-2i].

    Почему FFT верно.

    • База. При \(N=1\) многочлен постоянный. Его единственное значение равно единственному коэффициенту.
    • Переход. Предположим, что рекурсивные вызовы верно нашли значения \(E\) и \(O\). Формулы \(A(z)\) и \(A(-z)\) дают правильные значения для каждой пары противоположных точек. Всего пар \(N/2\), поэтому получаем все \(N\) нужных значений.

    Обратное преобразование¶

    Теперь у нас есть значения \(y_0,\ldots,y_{N-1}\). Нужно вернуть коэффициенты \(a_0,\ldots,a_{N-1}\).

    Прямая формула подставляет точку в многочлен:

    \[ y_r=\sum_{j=0}^{N-1}a_j\omega^{rj}. \]

    Знак \(\sum\) означает «сложить»: для каждого \(j\) берём коэффициент \(a_j\) и умножаем на нужную степень точки \(\omega^r\).

    Обратная формула очень похожа:

    \[ \boxed{a_j=\frac1N\sum_{r=0}^{N-1}y_r\omega^{-rj}.} \]

    Меняются только две вещи:

    1. Вместо поворота на \(2\pi/N\) идём в обратную сторону: угол \(-2\pi/N\).
    2. Делим результат на \(N\).

    Поэтому обратное преобразование вычисляет та же FFT с другим знаком угла. Дальше в коде будем делить на 2 при каждой рекурсивной склейке: за \(\log_2N\) уровней получится деление на \(N\). Дополнительно делить на \(N\) уже не надо.

    Почему обратная формула восстанавливает коэффициенты

    Подставим в неё прямую формулу. Для каждого исходного коэффициента \(a_\ell\) появится множитель

    \[ \frac1N\sum_{r=0}^{N-1}\omega^{r(\ell-j)}. \]

    При \(\ell=j\) все \(N\) слагаемых равны 1: множитель равен 1.

    При \(\ell\ne j\) обозначим \(q=\omega^{\ell-j}\). Тогда \(q\ne1\), но \(q^N=1\). Для суммы \(S=1+q+\ldots+q^{N-1}\) имеем \((q-1)S=q^N-1=0\), значит, \(S=0\).

    Нужный коэффициент остаётся, все остальные сокращаются. Это называют фильтром корней из единицы.

    Вернёмся к \((1+2x)(3+4x)\). Уже умеем получить все значения:

    Точка \(z\) \(A(z)\) \(B(z)\) \(C(z)\)
    \(1\) \(3\) \(7\) \(21\)
    \(i\) \(1+2i\) \(3+4i\) \(-5+10i\)
    \(-1\) \(-1\) \(-1\) \(1\)
    \(-i\) \(1-2i\) \(3-4i\) \(-5-10i\)

    Обратное FFT переводит последний столбец в [3, 10, 8, 0]. Например, коэффициент при \(x\):

    \[ c_1=\frac{21+(-5+10i)(-i)-1+(-5-10i)i}{4}=10. \]

    Это тот же ответ, который получили раскрытием скобок.

    Зачем дописывать нули¶

    Если в нашем примере взять \(N=2\), останутся только точки \(1\) и \(-1\). В обеих точках \(z^2=1\), поэтому слагаемые \(3\) и \(8z^2\) станут неразличимы.

    Обратное преобразование вернёт [11, 10]: старший коэффициент «завернулся» в начало. Это циклическая свёртка длины 2, а нужна обычная.

    Дополнение до \(N\ge n+m-1\) оставляет место всем коэффициентам ответа. Тогда заворачиваться нечему. После обратного FFT отбрасываем только добавленный хвост нулей.

    Сложность¶

    На одном уровне рекурсии суммарно обрабатываем \(N\) элементов. Каждый вызов делится на два вдвое меньших. Например, при \(N=8\) размеры идут так:

    Уровень Вызовы Всего элементов в склейках
    0 один по 8 8
    1 два по 4 8
    2 четыре по 2 8
    База восемь по 1 склейки не нужны

    Уровней со склейками — \(\log_2N\). Одно FFT работает за \(O(N\log N)\). Два прямых, одно обратное и \(N\) поэлементных умножений дают ту же оценку.

    Для \(N=131\,072\) в одном FFT \(17\) уровней, на каждом \(N/2\) бабочек. Три преобразования — \(3\,342\,336\) бабочек и ещё \(131\,072\) умножений значений. Бабочка сложнее одного обычного умножения, но разница с четырьмя миллиардами пар всё равно огромна.

    Память — \(O(N)\) одновременно: размеры подзадач вдоль ветки рекурсии складываются как \(N+N/2+N/4+\ldots<2N\), а на каждом уровне нужно лишь постоянное число массивов такого размера. Глубина стека — \(O(\log N)\).

    Где искать свёртку¶

    Общая формула для коэффициента произведения:

    \[ c_s=\sum_{j+k=s}a_jb_k. \]

    Она означает: для каждой суммы индексов собери произведения всех пар. За индексом может стоять вес, набранная сумма или позиция в строке.

    Что хранит коэффициент Что считает произведение
    Число объектов каждого веса число пар с каждой суммой весов — задача 2
    0 или 1: стоит ли единица в позиции число пар позиций; после разворота — для каждого расстояния, задача 3
    Число способов получить каждую сумму в двух независимых группах число способов получить общую сумму — объединение двух ДП
    Цифры длинных чисел суммы произведений цифр; после свёртки остаётся выполнить переносы разрядов

    Например, один выбор из чисел 0, 1, 2 кодируется многочленом \(F(x)=1+x+x^2\). В \(F(x)^2\) коэффициент при \(x^2\) равен 3: пары \((0,2)\), \((1,1)\), \((2,0)\). В \(F(x)^3\) коэффициент при \(x^3\) равен 7: шесть перестановок \((0,1,2)\) и тройка \((1,1,1)\).

    Это и есть динамика по сумме, записанная многочленами. При независимом объединении групп складываются их суммы и перемножаются количества способов. FFT ускоряет такой переход; произвольную ДП одним преобразованием ускорить нельзя.

    Точность¶

    В математике преобразования точные. double хранит числа приближённо, поэтому после обратного FFT вместо 10 может получиться 9.9999999998, а вместо нулевой мнимой части — маленький остаток.

    Если ответ должен быть целым, берём действительную часть и округляем до ближайшего целого: llround в C++, round в Python. Это исправляет погрешность меньше \(0.5\), но не любую ошибку.

    Даже ответ, помещающийся в long long, не гарантирует точности double. Например, \(1\,000\,000\,001^2=1\,000\,000\,002\,000\,000\,001\), а вычисление через double с последующим округлением может потерять последнюю единицу.

    Для небольших целых коэффициентов обычную FFT используют с округлением и проверкой на граничных тестах. Для больших коэффициентов или точного ответа по модулю нужны дополнительные приёмы: разбиение коэффициентов либо NTT, аналог FFT с вычислениями по подходящему простому модулю. Взять остаток от уже неточного ответа недостаточно.

    Код¶

    Реализация повторяет разобранную рекурсию. Функция fft получает массив длины степень двойки; convolve сама выбирает такую длину и дописывает нули. Оба входных массива convolve непустые.

    Прямое и обратное FFT¶

    В C++ функция меняет массив на месте. В Python возвращает новый. При прямом преобразовании результат — значения в порядке точек \(1,\omega,\omega^2,\ldots\); при обратном — коэффициенты \(a_0,a_1,\ldots\).

    #include <cmath>
#include <complex>
#include <vector>
using namespace std;
using cd = complex<double>;

void fft(vector<cd>& a, bool inverse) {
    int n = (int)a.size();
    if (n == 1) return;
    vector<cd> even(n / 2), odd(n / 2);
    for (int k = 0; k < n / 2; k++) {
        even[k] = a[2 * k];
        odd[k] = a[2 * k + 1];
    }
    fft(even, inverse);
    fft(odd, inverse);
    double angle = 2 * acos(-1.0) / n * (inverse ? -1 : 1);
    cd root(cos(angle), sin(angle)), w(1);
    for (int k = 0; k < n / 2; k++) {
        cd t = w * odd[k];
        a[k] = even[k] + t;
        a[k + n / 2] = even[k] - t;
        if (inverse) {
            a[k] /= 2;
            a[k + n / 2] /= 2;
        }
        w *= root;
    }
}

    import math

def fft(a, inverse=False):
    n = len(a)
    if n == 1:
        return a[:]
    even = fft(a[::2], inverse)
    odd = fft(a[1::2], inverse)
    angle = 2 * math.pi / n * (-1 if inverse else 1)
    root = complex(math.cos(angle), math.sin(angle))
    w = 1 + 0j
    result = [0j] * n
    for k in range(n // 2):
        t = w * odd[k]
        result[k] = even[k] + t
        result[k + n // 2] = even[k] - t
        if inverse:
            result[k] /= 2
            result[k + n // 2] /= 2
        w *= root
    return result

    Умножение¶

    Здесь вся схема целиком: два прямых FFT → умножение значений в одинаковых точках → обратное FFT → округление. Функции выше должны стоять перед этим кодом.

    vector<long long> convolve(const vector<long long>& a,
                          const vector<long long>& b) {
    int need = (int)(a.size() + b.size() - 1);
    int n = 1;
    while (n < need) n *= 2;
    vector<cd> fa(a.begin(), a.end()), fb(b.begin(), b.end());
    fa.resize(n);
    fb.resize(n);
    fft(fa, false);
    fft(fb, false);
    for (int k = 0; k < n; k++) fa[k] *= fb[k];
    fft(fa, true);
    vector<long long> result(need);
    for (int k = 0; k < need; k++) result[k] = llround(fa[k].real());
    return result;
}

    def convolve(a, b):
    need = len(a) + len(b) - 1
    n = 1
    while n < need:
        n *= 2
    fa = fft([complex(x) for x in a] + [0j] * (n - len(a)))
    fb = fft([complex(x) for x in b] + [0j] * (n - len(b)))
    values = [x * y for x, y in zip(fa, fb)]
    result = fft(values, inverse=True)
    return [round(x.real) for x in result[:need]]

    Для проверки: convolve([1, 2], [3, 4]) возвращает [3, 10, 8]. Ни деление на \(n\), ни повторное округление снаружи не нужны.

    Про скорость Python

    Версия на Python показывает тот же алгоритм и подходит для изучения и локальных проверок. У задач CSES ниже лимит 1 секунда, у Codeforces 993E — 2 секунды. На максимальных входах эта учебная Python-реализация выходит за такие лимиты. Для отправки в эти задачи используй C++.

    Умножение многочленов¶

    Сначала соберём все части алгоритма в решение исходной задачи. Здесь индексы массива — степени \(x\).

    Задача 1. Умножение многочленов¶

    Условие¶

    Даны коэффициенты двух многочленов: \(A(x)=a_0+a_1x+\ldots+a_{n-1}x^{n-1}\) и \(B(x)=b_0+b_1x+\ldots+b_{m-1}x^{m-1}\). Найдите коэффициенты \(C(x)=A(x)B(x)\).

    Вход: в первой строке \(n,m\) (\(1\le n,m\le10^5\)). Во второй — \(n\) целых чисел \(a_0,\ldots,a_{n-1}\), в третьей — \(m\) целых чисел \(b_0,\ldots,b_{m-1}\); все коэффициенты по модулю не больше 10.

    Выход: \(n+m-1\) коэффициентов \(c_0,\ldots,c_{n+m-2}\) через пробел. Нули в конце тоже выводятся.

    Ввод
    2 2
1 2
3 4
    Вывод
    3 10 8

    Идея¶

    Обычное раскрытие скобок перебирает \(nm\) пар — до \(10^{10}\). Вместо этого применим схему из раздела «Алгоритм»: значения в одинаковых корнях из единицы можно умножить попарно, а обратное FFT восстановит коэффициенты.

    Решение¶

    Шаг рецепта В этой задаче
    Длина ответа \(n+m-1\)
    Подготовка выбираем степень двойки \(N\ge n+m-1\), дописываем нули
    Прямые преобразования считаем значения \(A\) и \(B\) в одних и тех же \(N\) точках
    Умножение для каждого \(k\) получаем \(A(\omega^k)B(\omega^k)\)
    Обратное преобразование возвращаем коэффициенты, округляем
    Ответ первые \(n+m-1\) коэффициентов

    Доказательство.

    • База. После дополнения нулями массивы задают прежние многочлены. Степень \(C\) меньше \(N\), значит, выбранных точек достаточно.
    • Переход. Два прямых FFT дают правильные значения \(A\) и \(B\). По тождеству \(C(z)=A(z)B(z)\) их попарные произведения — значения \(C\). Обратное преобразование восстанавливает его коэффициенты. Корректность обоих преобразований доказана в разделе «Алгоритм»; реализация использует округление с оговорками из подраздела «Точность».

    Сложность. \(O(N\log N)\) времени, \(O(N)\) памяти, где \(N\) — выбранная степень двойки. Поскольку \(N<2(n+m)\), можно записать и \(O((n+m)\log(n+m))\) времени, \(O(n+m)\) памяти.

    Код. Во всех задачах ниже добавь перед программой обе общие функции из раздела «Код». Заново писать FFT для каждой задачи не нужно.

    #include <iostream>

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m;
    cin >> n >> m;
    vector<long long> a(n), b(m);
    for (auto& x : a) cin >> x;
    for (auto& x : b) cin >> x;
    auto c = convolve(a, b);
    for (int k = 0; k < n + m - 1; k++)
        cout << c[k] << (k + 1 < n + m - 1 ? ' ' : '\n');
}

    Применения свёртки¶

    В следующих задачах многочлены в условии не упоминаются. Мы сами решим, что хранить в коэффициентах, чтобы нужные пары собрались в произведении.

    Задача 2. Яблоки и бананы¶

    Условие¶

    CSES · Apples and Bananas.

    Есть \(n\) яблок и \(m\) бананов. Вес каждого — целое число от 1 до \(k\). Для каждого \(w\) от 2 до \(2k\) найдите количество способов выбрать одно яблоко и один банан с суммарным весом \(w\). Разные фрукты одного веса считаются разными вариантами.

    Вход: числа \(k,n,m\) (\(1\le k,n,m\le2\cdot10^5\)), затем \(n\) весов яблок и \(m\) весов бананов.

    Выход: \(2k-1\) чисел — ответы для \(w=2,3,\ldots,2k\).

    Ввод
    5 3 4
5 2 5
4 3 2 3
    Вывод
    0 0 1 2 1 2 4 2 0

    Пояснение: сумму 8 дают два яблока веса 5 и два банана веса 3 — \(2\cdot2=4\) пары.

    Идея¶

    Перебирать пары нельзя: их бывает \(4\cdot10^{10}\). Но сами веса ограничены \(k\).

    Пусть \(a_u\) — количество яблок веса \(u\), а \(b_v\) — количество бананов веса \(v\). Пара весов \(u,v\) даёт \(a_ub_v\) способов. Для суммарного веса \(w\) надо сложить эти произведения по всем \(u+v=w\). Это ровно коэффициент свёртки.

    Решение¶

    Шаг рецепта В этой задаче
    Коэффициенты частоты весов: a[вес] и b[вес]
    Нулевой индекс a[0] = b[0] = 0: фруктов веса 0 нет
    Умножение c = convolve(a, b)
    Ответ для веса \(w\) c[w]
    Что выводим c[2], …, c[2*k]

    На примере \(A(x)=x^2+2x^5\), \(B(x)=x^2+2x^3+x^4\). Коэффициент при \(x^8\) равен \(2\cdot2=4\).

    Доказательство.

    • База. Массивы частот учитывают каждый фрукт ровно один раз в коэффициенте его веса.
    • Переход. Произведение \(a_ub_v\) учитывает все пары этих весов. В c[w] попадают ровно группы с \(u+v=w\); разные группы не пересекаются, поэтому ни одна пара не пропущена и не посчитана дважды.

    Тип данных. Один ответ может быть \(nm=4\cdot10^{10}\) — нужен long long.

    Сложность. Чтение и заполнение частот — \(O(n+m+k)\), свёртка — \(O(k\log(k+1))\). Всего \(O(n+m+k\log(k+1))\) времени и \(O(k)\) памяти в C++; показанный Python-код дополнительно хранит вход, поэтому использует \(O(n+m+k)\) памяти.

    Код.

    #include <iostream>

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int k, n, m, x;
    cin >> k >> n >> m;
    vector<long long> a(k + 1), b(k + 1);
    for (int j = 0; j < n; j++) {
        cin >> x;
        a[x]++;
    }
    for (int j = 0; j < m; j++) {
        cin >> x;
        b[x]++;
    }
    auto c = convolve(a, b);
    for (int w = 2; w <= 2 * k; w++)
        cout << c[w] << (w < 2 * k ? ' ' : '\n');
}

    import sys

data = iter(map(int, sys.stdin.buffer.read().split()))

for _ in range(n):
    a[next(data)] += 1
for _ in range(m):
    b[next(data)] += 1
c = convolve(a, b)
print(*c[2:2 * k + 1])

    На примере из условия программа печатает 0 0 1 2 1 2 4 2 0.

    Задача 3. Пары единиц¶

    Условие¶

    CSES · One Bit Positions.

    Дана строка \(s\) из нулей и единиц, позиции нумеруются от 0 до \(n-1\). Для каждого расстояния \(d=1,\ldots,n-1\) найдите количество пар позиций \(j<r\), для которых \(r-j=d\) и оба символа равны 1.

    Вход: одна бинарная строка длины \(2\le n\le2\cdot10^5\).

    Выход: \(n-1\) чисел — количество пар для каждого расстояния по возрастанию.

    Ввод
    1001011010
    Вывод
    1 2 3 0 2 1 0 1 0

    Идея¶

    Для одного расстояния можно пройти по строке. Но для всех расстояний суммарно получится порядка \(n^2\) проверок.

    Запишем биты в массив \(a\): 1 означает, что в позиции есть единица, 0 — что нет. Хотим складывать произведения \(a_ra_j\) по одинаковой разности \(r-j\). А свёртка группирует по сумме индексов. Как превратить разность в сумму?

    Развернём второй массив: \(b_{n-1-j}=a_j\). Тогда пара исходных позиций \(r,j\) попадёт в коэффициент с индексом

    \[ r+(n-1-j)=n-1+(r-j)=n-1+d. \]

    Значит, одно умножение сразу даст ответы для всех расстояний.

    Решение¶

    Шаг рецепта В этой задаче
    Первый массив биты строки \(a_0,\ldots,a_{n-1}\)
    Второй массив те же биты в обратном порядке
    Умножение c = convolve(a, reversed_a)
    Ответ для расстояния \(d\) c[n-1+d]
    Что выводим c[n], …, c[2*n-2]

    На маленьком примере 1011:

    • \(a=\) [1, 0, 1, 1], \(b=\) [1, 1, 0, 1];
    • свёртка \(c=\) [1, 1, 1, 3, 1, 1, 1];
    • ответы для расстояний 1, 2, 3 — c[4], c[5], c[6], то есть 1 1 1.

    Центральный коэффициент c[n-1] равен числу единиц: там каждая позиция сочетается с самой собой. В ответ его не включаем. Для \(d>0\) порядок позиций уже задан, поэтому делить на 2 не надо.

    Доказательство.

    • База. Произведение \(a_ra_j\) равно 1 ровно тогда, когда обе исходные позиции содержат единицы.
    • Переход. После разворота эта пара попадает ровно в c[n-1+(r-j)]. Поэтому коэффициент для фиксированного \(d>0\) считает все и только пары с \(r-j=d\), каждую один раз.

    Сложность. \(O(n\log n)\) времени, \(O(n)\) памяти.

    Код.

    #include <algorithm>
#include <iostream>
#include <string>

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    string s;
    cin >> s;
    int n = (int)s.size();
    vector<long long> a(n);
    for (int j = 0; j < n; j++) a[j] = s[j] - '0';
    auto b = a;
    reverse(b.begin(), b.end());
    auto c = convolve(a, b);
    for (int d = 1; d < n; d++)
        cout << c[n - 1 + d] << (d + 1 < n ? ' ' : '\n');
}

    import sys

print(*c[n:2 * n - 1])

    Задача 4. Подотрезки¶

    Условие¶

    Упражнение

    993E · Никита и порядковая статистика.

    Дан массив \(a_1,\ldots,a_n\) и число \(x\). Для каждого \(k=0,1,\ldots,n\) найдите количество непустых подотрезков с ровно \(k\) элементами меньше \(x\). Подотрезок — все элементы с некоторого индекса \(l\) до некоторого \(r\) включительно.

    Вход: числа \(n,x\) (\(1\le n\le2\cdot10^5\), \(|x|\le10^9\)), затем \(n\) целых чисел \(a_i\) (\(|a_i|\le10^9\)).

    Выход: \(n+1\) чисел — ответы для \(k=0,1,\ldots,n\).

    Ввод
    5 3
1 2 3 4 5
    Вывод
    6 5 4 0 0 0

    Попробуй соединить идею предыдущей задачи с префиксными суммами. Случай \(k=0\) потребует отдельного внимания.

    Идея¶

    Подсказка

    Замени каждый элемент на 1, если он меньше \(x\), и на 0 иначе. Пусть \(p_r\) — сумма первых \(r\) полученных чисел, включая \(p_0=0\). Тогда нужное количество на подотрезке \([l,r]\) равно \(p_r-p_{l-1}\). Надо посчитать пары значений префиксов с каждой возможной разностью.

    Решение¶

    Решение за O(n log n)

    Соберём частоты: \(f_v\) — сколько из \(n+1\) префиксов имеют значение \(v\). Развернём массив \(f\) длины \(n+1\) и посчитаем свёртку.

    Шаг рецепта В этой задаче
    Подготовка \(p_0=0\); далее прибавляем 1 за элемент меньше \(x\)
    Коэффициенты \(f_v\) — количество префиксов со значением \(v\)
    Умножение \(c=f*\operatorname{reverse}(f)\)
    Ответ для \(k>0\) \(c_{n+k}\): середина теперь имеет индекс \(n\)
    Ответ для \(k=0\) сумма \(f_v(f_v-1)/2\) по всем \(v\)

    Для примера \(p=\) [0, 1, 2, 2, 2, 2], поэтому \(f=\) [1, 1, 4, 0, 0, 0]. Для \(k=1\) получаем \(1\cdot1+4\cdot1=5\), для \(k=2\) — \(4\cdot1=4\). Равных префиксов со значением 2 четыре: они дают \(4\cdot3/2=6\) подотрезков с \(k=0\).

    Доказательство.

    • База. Каждому непустому подотрезку соответствует ровно одна пара префиксов: перед его началом и на его конце.
    • Переход. При \(k>0\) частоты и разворот считают все пары значений с разностью \(k\), как в задаче 3. Порядок концов не теряется: префиксные суммы не убывают, поэтому префикс с большей суммой обязательно стоит позже префикса с меньшей. При \(k=0\) из \(f_v\) равных префиксов выбираем два различных. Неупорядоченная пара уже однозначно задаёт более ранний и более поздний конец, поэтому вариантов \(f_v(f_v-1)/2\).

    Тип данных. Подотрезков бывает \(n(n+1)/2\), до \(20\,000\,100\,000\), нужен long long. Центральный коэффициент свёртки для \(k=0\) напрямую не подходит: он включает пары префикса с собой и оба порядка разных префиксов.

    Сложность. Частоты собираем за \(O(n)\), свёртка занимает \(O(n\log n)\) времени и \(O(n)\) памяти.

    Код. Добавь общие fft и convolve.

    #include <algorithm>
#include <iostream>

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, x, value, p = 0;
    cin >> n >> x;
    vector<long long> f(n + 1);
    f[0] = 1;  // пустой префикс тоже нужен
    for (int j = 0; j < n; j++) {
        cin >> value;
        p += (value < x);
        f[p]++;
    }
    auto rev = f;
    reverse(rev.begin(), rev.end());
    auto c = convolve(f, rev);
    long long zero = 0;
    for (long long count : f) zero += count * (count - 1) / 2;
    cout << zero;
    for (int k = 1; k <= n; k++) cout << ' ' << c[n + k];
    cout << '\n';
}

    import sys

data = list(map(int, sys.stdin.buffer.read().split()))
n, x = data[:2]
f = [0] * (n + 1)
f[0] = 1
p = 0
for value in data[2:]:
    p += value < x
    f[p] += 1
c = convolve(f, f[::-1])
zero = sum(count * (count - 1) // 2 for count in f)
print(zero, *c[n + 1:2 * n + 1])

    На примере из условия программа печатает 6 5 4 0 0 0.

    Типичные ошибки¶

    1. Слишком короткое преобразование. Нужно \(N\ge n+m-1\), а не только \(N\ge\max(n,m)\). В задаче 1 ошибочный размер 2 превращает 3 10 8 в 11 10.
    2. Знак угла и нормировка не согласованы. В этом коде прямое FFT использует плюс, обратное — минус и деление на 2 на каждом уровне. Если дополнительно поделить на \(N\), ответ задачи 1 станет в \(N\) раз меньше. Проверь, что обратное FFT после прямого возвращает исходный массив.
    3. Округление и типы данных. int(real + 0.5) неправильно округляет отрицательные числа; в задаче 1 используй llround или round. А задачи 2 и 4 требуют 64-битных целых. Точность double — отдельное ограничение: остаток по модулю после неточного вычисления её не исправит.
    4. Потеря повторов. В задаче 2 коэффициент — количество фруктов, а не просто 0 или 1. Иначе ответ для веса 8 в примере станет 1 вместо 4.
    5. Неверный индекс после разворота. Для массива длины \(n\) в задаче 3 ответ лежит в c[n-1+d], для частот длины \(n+1\) в задаче 4 — в c[n+k]. Проверь 1011: ответы 1 1 1. Центральный коэффициент не является ответом для положительного расстояния.
