## Зачем это нужно

Есть $10^5$ чисел и $10^5$ команд: заменить одно число или узнать сумму на отрезке.

- **В лоб:** сумма отрезка — до $10^5$ сложений, на все команды — до $10^{10}$.
- **Префиксные суммы:** сумма — одно вычитание, но после каждой замены их приходится пересчитывать — снова до $10^{10}$.
- **Дерево отрезков:** замена — 17 шагов по уровням, а любая сумма собирается не больше чем из 34 готовых кусков.

Это задача 1 — ниже её точное условие и решение.

## Идея

Возьмём массив `5 8 6 3 2 7 2 6`. Разобьём его пополам, каждую половину — снова пополам, пока не останутся отдельные числа. Для каждого куска заранее посчитаем сумму.

## Алгоритм

### Устройство

- **Вершина** отвечает за отрезок $[l, r]$ и хранит сумму на нём. Корень отвечает за весь массив $[1, n]$.
- Если $l < r$, у вершины два сына: $[l, m]$ и $[m+1, r]$, где $m = \lfloor (l+r)/2 \rfloor$. Вершина с $l = r$ — **лист**, она хранит само число.
- Номера вершин: корень — 1, сыновья вершины $v$ — $2v$ и $2v+1$. Тогда всё дерево помещается в массив `t` размера $4n$.

??? note "Почему хватает 4n"
    Отрезок каждый раз делится пополам с округлением вверх, поэтому глубина дерева равна $\lceil \log_2 n \rceil$. Вершины глубины $d$ имеют номера меньше $2^{d+1}$, значит, все номера меньше $2^{\lceil \log_2 n \rceil + 1} < 4n$. Размера $2n$ не хватает: при $n = 6$ встречается вершина с номером 13.

### Построение

Лист копирует своё число, остальные вершины — сумма двух сыновей. Строим рекурсивно: сначала сыновья, потом вершина. Каждая из $2n - 1$ вершин считается один раз — время $O(n)$.

### Изменение

Чтобы заменить $a_i$, спускаемся от корня к листу $i$ — каждый раз в того сына, чей отрезок содержит $i$. В листе пишем новое число, на обратном пути пересчитываем суммы. На каждом уровне меняется одна вершина — время $O(\log n)$.

### Запрос суммы

`query` для вершины с отрезком $[l, r]$ возвращает сумму той части запроса $[ql, qr]$, что лежит внутри $[l, r]$:

1. отрезки не пересекаются — вернуть 0;
2. $[l, r]$ целиком внутри $[ql, qr]$ — вернуть готовую сумму вершины;
3. иначе — сложить ответы двух сыновей.

**Почему быстро.** Вершина попадает в случай 3, только если её отрезок содержит границу запроса — $ql$ или $qr$. Отрезки одного уровня не пересекаются, поэтому таких вершин на уровне не больше двух, и на следующем уровне они вызывают не больше четырёх сыновей. Для $n = 10^5$ уровней 17, а готовых кусков — не больше двух на уровень, то есть не больше 34.

**Почему верно.**

- **База.** Лист хранит своё число — сумму отрезка длины 1.
- **Переход.** Если сыновья хранят верные суммы своих половин, то сумма вершины тоже верна. Запрос раскладывает $[ql, qr]$ на непересекающиеся куски: каждая позиция отрезка лежит ровно в одном из сыновей, поэтому попадает в ответ ровно один раз.

### Сложность

Построение — $O(n)$, изменение и запрос — $O(\log n)$, память — $O(n)$.

### Код

Позиции — от 1 до $n$, `a[0]` не используется. Массив `t` и число `n` общие для всех функций.

=== "C++"

    ```cpp
    #include <vector>
    using namespace std;

    int n;
    vector<long long> t;  // t[v] — сумма на отрезке вершины v; размер 4n

    void build(const vector<long long>& a, int v, int l, int r) {
        if (l == r) {
            t[v] = a[l];
            return;
        }
        int m = (l + r) / 2;
        build(a, 2 * v, l, m);
        build(a, 2 * v + 1, m + 1, r);
        t[v] = t[2 * v] + t[2 * v + 1];
    }

    void update(int v, int l, int r, int pos, long long x) {
        if (l == r) {
            t[v] = x;
            return;
        }
        int m = (l + r) / 2;
        if (pos <= m) update(2 * v, l, m, pos, x);
        else update(2 * v + 1, m + 1, r, pos, x);
        t[v] = t[2 * v] + t[2 * v + 1];  // пересчёт на обратном пути
    }

    long long query(int v, int l, int r, int ql, int qr) {
        if (qr < l || r < ql) return 0;       // не пересекаются
        if (ql <= l && r <= qr) return t[v];  // готовый кусок
        int m = (l + r) / 2;
        return query(2 * v, l, m, ql, qr) + query(2 * v + 1, m + 1, r, ql, qr);
    }
    ```

=== "Python"

    ```python
    t = []  # t[v] — сумма на отрезке вершины v; программа создаёт [0] * (4 * n)

    def update(v, l, r, pos, x):
        if l == r:
            t[v] = x
            return

        if pos <= m:
            update(2 * v, l, m, pos, x)
        else:
            update(2 * v + 1, m + 1, r, pos, x)
        t[v] = t[2 * v] + t[2 * v + 1]  # пересчёт на обратном пути

    def query(v, l, r, ql, qr):

            return 0
        if ql <= l and r <= qr:  # готовый кусок
            return t[v]
        m = (l + r) // 2
        return query(2 * v, l, m, ql, qr) + query(2 * v + 1, m + 1, r, ql, qr)
    ```

## Запросы на отрезке

Вершина хранит ответ для своего отрезка и умеет склеивать ответы двух половин. От задачи к задаче меняется только то, что хранится в вершине.

### Задача 1. Сумма с изменениями

#### Условие

Дан массив $a_1, \ldots, a_n$. Выполните $q$ команд двух видов:

- `1 i x` — присвоить $a_i = x$;
- `2 l r` — вывести сумму $a_l + a_{l+1} + \ldots + a_r$.

- **Вход:** в первой строке $n$ и $q$ ($1 \le n, q \le 10^5$), во второй — $a_1, \ldots, a_n$ ($|a_i| \le 10^9$), затем $q$ команд; $1 \le i \le n$, $|x| \le 10^9$, $1 \le l \le r \le n$.
- **Выход:** для каждой команды второго вида — сумма в отдельной строке.

<div class="grid" markdown>

```text title="Ввод"
8 4
5 8 6 3 2 7 2 6
2 3 7
1 6 1
2 3 7
2 1 8
```

```text title="Вывод"
20
14
33
```

</div>

#### Идея

В лоб — до $10^5$ сложений на один запрос и $10^{10}$ на все. Дерево из раздела «Алгоритм» делает и замену, и запрос за $O(\log n)$: замена меняет по одной вершине на уровне, а сумма собирается из готовых кусков — как на схемах в разделе «Идея».

#### Решение

| Шаг алгоритма | В этой задаче |
|---|---|
| **Вершина хранит** | сумму своего отрезка |
| **Лист** | само число $a_i$ |
| **Склейка** | сумма левого сына + сумма правого |
| **Команда 1** | `update`: новое число в листе, пересчёт сумм на пути к корню |
| **Команда 2** | `query`: сумма готовых кусков, из которых складывается $[l, r]$ |

На примере: первый запрос складывает куски $[3..4]$, $[5..6]$ и $[7..7]$: $9 + 9 + 2 = 20$. Замена $a_6 = 1$ меняет вершины $7 \to 1$, $9 \to 3$, $17 \to 11$, $39 \to 33$. Второй запрос: $9 + 3 + 2 = 14$, третий берёт готовый корень: $33$.

**Доказательство.** Устройство дерева и запрос обоснованы в разделе «Алгоритм».

- **База.** После `build` каждая вершина хранит сумму своего отрезка.
- **Переход.** `update` меняет ровно те вершины, чьи отрезки содержат $i$, и пересчитывает их снизу вверх; суммы остальных вершин не изменились. Значит, после каждой команды все вершины снова хранят верные суммы, и `query` возвращает верный ответ.

**Тип данных.** Сумма — до $10^5 \cdot 10^9 = 10^{14}$, нужен `long long`.

**Сложность.** $O(n + q \log n)$ времени, $O(n)$ памяти.

**Код.** Перед программой добавь общие функции из раздела «Код».

=== "C++"

    ```cpp
    #include <iostream>

    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        int q;
        cin >> n >> q;
        vector<long long> a(n + 1);
        for (int i = 1; i <= n; i++) cin >> a[i];
        t.assign(4 * n, 0);
        build(a, 1, 1, n);
        while (q--) {
            int type, u;
            long long w;
            cin >> type >> u >> w;
            if (type == 1) update(1, 1, n, u, w);
            else cout << query(1, 1, n, u, (int)w) << '\n';
        }
    }
    ```

=== "Python"

На примере из условия программа печатает `20`, `14` и `33`.

### Задача 2. Минимум и сколько раз он встречается

#### Условие

Дан массив $a_1, \ldots, a_n$. Выполните $q$ команд двух видов:

- `1 i x` — присвоить $a_i = x$;
- `2 l r` — вывести минимум на отрезке $[l, r]$ и сколько раз он там встречается.

- **Вход:** как в задаче 1.
- **Выход:** для каждой команды второго вида — два числа через пробел.

<div class="grid" markdown>

```text title="Ввод"
8 4
5 8 6 3 2 7 2 6
2 1 8
2 1 4
1 5 9
2 1 8
```

```text title="Вывод"
2 2
3 1
2 1
```

</div>

#### Идея

Сумму мы склеивали из сумм половин. Минимум склеивается так же: минимум отрезка — меньший из минимумов половин. А количество? Если минимумы половин разные, побеждает меньший вместе со своим количеством; если равны — количества складываются. Значит, в вершине храним пару: минимум и количество.

#### Решение

| Шаг алгоритма | В этой задаче |
|---|---|
| **Вершина хранит** | пару: минимум и сколько раз он встречается |
| **Лист** | $(a_i, 1)$ |
| **Склейка** | меньший минимум побеждает; при равных количества складываются |
| **Пустой кусок** | $(+\infty, 0)$: при склейке не меняет ответ |
| **Команды** | как в задаче 1, только вместо `+` — склейка пар |

На примере: половины $[1..4]$ и $[5..8]$ хранят $(3, 1)$ и $(2, 2)$, в корне — $(2, 2)$: двойки стоят на позициях 5 и 7. После $a_5 = 9$ правая половина хранит $(2, 1)$, корень — тоже $(2, 1)$.

**Доказательство.**

- **База.** В листе минимум — само число, и встречается оно один раз.
- **Переход.** Минимум отрезка — меньший из минимумов половин. Каждое вхождение минимума лежит ровно в одной половине. Если у половины минимум больше общего, вхождений общего минимума в ней нет; иначе их столько, сколько посчитано в ней. Ровно это и делает склейка.

**Сложность.** Как в задаче 1: $O(n + q \log n)$ времени, $O(n)$ памяти.

**Код.** Отдельная программа: схема та же, но вместо чисел — пары.

=== "C++"

    ```cpp
    #include <climits>
    #include <iostream>
    #include <vector>
    using namespace std;

    using Node = pair<long long, int>;  // минимум и сколько раз он встречается
    const Node EMPTY = {LLONG_MAX, 0};  // пустой кусок проигрывает любому минимуму
    int n;
    vector<Node> t;

    Node combine(Node x, Node y) {
        if (x.first != y.first) return min(x, y);  // меньший минимум побеждает
        return {x.first, x.second + y.second};     // равные: складываем количества
    }

    void build(const vector<long long>& a, int v, int l, int r) {
        if (l == r) {
            t[v] = {a[l], 1};
            return;
        }
        int m = (l + r) / 2;
        build(a, 2 * v, l, m);
        build(a, 2 * v + 1, m + 1, r);
        t[v] = combine(t[2 * v], t[2 * v + 1]);
    }

    void update(int v, int l, int r, int pos, long long x) {
        if (l == r) {
            t[v] = {x, 1};
            return;
        }
        int m = (l + r) / 2;
        if (pos <= m) update(2 * v, l, m, pos, x);
        else update(2 * v + 1, m + 1, r, pos, x);
        t[v] = combine(t[2 * v], t[2 * v + 1]);
    }

    Node query(int v, int l, int r, int ql, int qr) {
        if (qr < l || r < ql) return EMPTY;
        if (ql <= l && r <= qr) return t[v];
        int m = (l + r) / 2;
        return combine(query(2 * v, l, m, ql, qr), query(2 * v + 1, m + 1, r, ql, qr));
    }

    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        int q;
        cin >> n >> q;
        vector<long long> a(n + 1);
        for (int i = 1; i <= n; i++) cin >> a[i];
        t.assign(4 * n, EMPTY);
        build(a, 1, 1, n);
        while (q--) {
            int type, u;
            long long w;
            cin >> type >> u >> w;
            if (type == 1) {
                update(1, 1, n, u, w);
            } else {
                Node res = query(1, 1, n, u, (int)w);
                cout << res.first << ' ' << res.second << '\n';
            }
        }
    }
    ```

=== "Python"

    ```python
    import sys

    EMPTY = (float("inf"), 0)  # пустой кусок проигрывает любому минимуму

    def combine(x, y):
        if x[0] != y[0]:
            return min(x, y)  # меньший минимум побеждает

            return

        build(a, 2 * v, l, m)
        build(a, 2 * v + 1, m + 1, r)
        t[v] = combine(t[2 * v], t[2 * v + 1])

    def update(v, l, r, pos, x):
        if l == r:
            t[v] = (x, 1)
            return
        m = (l + r) // 2
        if pos <= m:
            update(2 * v, l, m, pos, x)
        else:
            update(2 * v + 1, m + 1, r, pos, x)
        t[v] = combine(t[2 * v], t[2 * v + 1])

    def query(v, l, r, ql, qr):
        if qr < l or r < ql:
            return EMPTY
        if ql <= l and r <= qr:
            return t[v]
        m = (l + r) // 2
        return combine(query(2 * v, l, m, ql, qr), query(2 * v + 1, m + 1, r, ql, qr))

    data = sys.stdin.buffer.read().split()
    n, q = int(data[0]), int(data[1])
    a = [0] + [int(x) for x in data[2:2 + n]]

        if kind == 1:
            update(1, 1, n, u, w)

            low, count = query(1, 1, n, u, w)
            out.append(f"{low} {count}")
    print("\n".join(out))
    ```

## Спуск по дереву

Иногда нужен не ответ на отрезке, а место в массиве, где выполняется условие. Тогда спускаемся от корня и каждый раз выбираем одного сына.

### Задача 3. k-я единица

#### Условие

Дан массив $a_1, \ldots, a_n$ из нулей и единиц. Выполните $q$ команд двух видов:

- `1 i` — заменить $a_i$ на противоположное: 0 на 1, 1 на 0;
- `2 k` — вывести номер $k$-й слева единицы. Гарантируется, что единиц не меньше $k$.

- **Вход:** в первой строке $n$ и $q$ ($1 \le n, q \le 10^5$), во второй — $a_1, \ldots, a_n$, затем $q$ команд.
- **Выход:** для каждой команды второго вида — номер позиции в отдельной строке.

<div class="grid" markdown>

```text title="Ввод"
8 4
1 0 1 1 0 0 1 0
2 3
1 2
2 3
2 5
```

```text title="Вывод"
4
3
7
```

</div>

#### Идея

Сумма на префиксе $[1, p]$ — это число единиц до позиции $p$. Можно бинпоиском искать наименьшее $p$ с суммой не меньше $k$: $\log n$ проверок по $O(\log n)$ каждая — $O(\log^2 n)$. Но дерево позволяет быстрее: в каждой вершине мы знаем, сколько единиц в левой половине, и сразу решаем, куда идти.

#### Решение

| Шаг алгоритма | В этой задаче |
|---|---|
| **Вершина хранит** | количество единиц — сумму, как в задаче 1 |
| **Спуск** | если $k$ не больше числа единиц в левом сыне — налево; иначе вычитаем их из $k$ и идём направо |
| **Остановка** | в листе: его номер — ответ |
| **Команда 1** | `update(i, 1 - a[i])` |

<figure markdown="span">
  ![Спуск за третьей единицей в массиве 1 0 1 1 0 0 1 0: налево в корне, направо дважды, ответ — позиция 4](img/segment-tree/descent-light.svg#only-light){ width="640" }
  ![Спуск за третьей единицей в массиве 1 0 1 1 0 0 1 0: налево в корне, направо дважды, ответ — позиция 4](img/segment-tree/descent-dark.svg#only-dark){ width="640" }
  <figcaption>Ищем третью единицу. В левой половине корня их 3 — идём налево. В [1..2] одна — идём направо и ищем уже вторую, потом первую.</figcaption>
</figure>

**Доказательство.** Утверждение: искомая позиция — $k$-я единица отрезка текущей вершины.

- **База.** В корне это условие задачи.
- **Переход.** Пусть в левом сыне $s$ единиц. Если $k \le s$, искомая единица лежит в левом сыне и там она $k$-я. Иначе она в правом сыне, а перед ней стоят все $s$ единиц левого — в правом она $(k-s)$-я. В листе $k = 1$, и его позиция — ответ.

**Сложность.** Спуск — один шаг на уровень: $O(\log n)$ на команду, всего $O(n + q \log n)$.

**Код.** Перед программой добавь общие функции из раздела «Код».

=== "C++"

    ```cpp
    #include <iostream>

    int kth(int v, int l, int r, int k) {
        if (l == r) return l;
        int m = (l + r) / 2;
        if (k <= t[2 * v]) return kth(2 * v, l, m, k);
        return kth(2 * v + 1, m + 1, r, k - t[2 * v]);  // единицы левого сына пропускаем
    }

    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        int q;
        cin >> n >> q;
        vector<long long> a(n + 1);
        for (int i = 1; i <= n; i++) cin >> a[i];
        t.assign(4 * n, 0);
        build(a, 1, 1, n);
        while (q--) {
            int type, x;
            cin >> type >> x;
            if (type == 1) {
                a[x] = 1 - a[x];
                update(1, 1, n, x, a[x]);
            } else {
                cout << kth(1, 1, n, x) << '\n';
            }
        }
    }
    ```

=== "Python"

    ```python
    import sys

    def kth(v, l, r, k):
        if l == r:
            return l
        m = (l + r) // 2
        if k <= t[2 * v]:
            return kth(2 * v, l, m, k)
        return kth(2 * v + 1, m + 1, r, k - t[2 * v])  # единицы левого сына пропускаем

    data = sys.stdin.buffer.read().split()
    n, q = int(data[0]), int(data[1])
    a = [0] + [int(x) for x in data[2:2 + n]]
    t = [0] * (4 * n)
    build(a, 1, 1, n)
    out = []
    for j in range(q):
        kind, x = int(data[2 + n + 2 * j]), int(data[3 + n + 2 * j])
        if kind == 1:
            a[x] = 1 - a[x]
            update(1, 1, n, x, a[x])
        else:
            out.append(kth(1, 1, n, x))
    print("\n".join(map(str, out)))
    ```

На примере из условия программа печатает `4`, `3` и `7`.

## Изменения на отрезке

Команда может менять сразу много чисел. Иногда её удаётся свести к замене одного-двух чисел в другом массиве.

### Задача 4. Прибавление на отрезке

#### Условие

!!! question "Упражнение"
    Дан массив $a_1, \ldots, a_n$. Выполните $q$ команд двух видов:

    - `1 l r x` — прибавить $x$ ко всем числам $a_l, \ldots, a_r$;
    - `2 i` — вывести $a_i$.

    - **Вход:** в первой строке $n$ и $q$ ($1 \le n, q \le 10^5$), во второй — $a_1, \ldots, a_n$ ($|a_i| \le 10^9$), затем $q$ команд; $1 \le l \le r \le n$, $|x| \le 10^9$.
    - **Выход:** для каждой команды второго вида — значение $a_i$ в отдельной строке.

    <div class="grid" markdown>

    ```text title="Ввод"
    5 4
    1 2 3 4 5
    1 2 4 10
    2 3
    1 1 5 -1
    2 5
    ```

    ```text title="Вывод"
    13
    4
    ```

    </div>

    Попробуй свести задачу к задаче 1.

#### Идея

??? tip "Подсказка"
    Храни в дереве не сами числа, а разности соседей: $d_i = a_i - a_{i-1}$, считая $a_0 = 0$. Тогда $a_i = d_1 + \ldots + d_i$ — сумма на префиксе. А прибавление на отрезке меняет только два числа $d$.

#### Решение

??? success "Решение за O((n + q) log n)"
    | Шаг алгоритма | В этой задаче |
    |---|---|
    | **Массив в дереве** | разности $d_i = a_i - a_{i-1}$ |
    | **Команда 1** | $d_l$ увеличить на $x$; если $r < n$, то $d_{r+1}$ уменьшить на $x$ — два вызова `update` |
    | **Команда 2** | $a_i$ — это `query` на $[1, i]$ |

    На примере: $d = $ `[1, 1, 1, 1, 1]`. После `1 2 4 10`: $d_2 = 11$, $d_5 = -9$, и $a_3 = 1 + 11 + 1 = 13$. После `1 1 5 -1`: $d_1 = 0$, правой границы внутри массива нет, и $a_5 = 0 + 11 + 1 + 1 - 9 = 4$.

    **Доказательство.**

    - **База.** Сумма разностей сокращается: $(a_1 - a_0) + (a_2 - a_1) + \ldots + (a_i - a_{i-1}) = a_i$.
    - **Переход.** После прибавления $x$ на $[l, r]$ разность $d_l$ растёт на $x$, а $d_{r+1}$ уменьшается на $x$. Остальные не меняются: внутри отрезка оба соседа выросли на $x$, снаружи оба остались прежними.

    **Тип данных.** Числа растут до $10^9 + 10^5 \cdot 10^9 \approx 10^{14}$ — нужен `long long`.

    **Сложность.** $O(n + q \log n)$ времени, $O(n)$ памяти.

    **Код.** Общие функции из раздела «Код» — без изменений.

    === "C++"

        ```cpp
        #include <iostream>

        int main() {
            ios::sync_with_stdio(false);
            cin.tie(nullptr);
            int q;
            cin >> n >> q;
            vector<long long> a(n + 1), d(n + 2, 0);
            for (int i = 1; i <= n; i++) {
                cin >> a[i];
                d[i] = a[i] - a[i - 1];
            }
            t.assign(4 * n, 0);
            build(d, 1, 1, n);
            while (q--) {
                int type;
                cin >> type;
                if (type == 1) {
                    int l, r;
                    long long x;
                    cin >> l >> r >> x;
                    d[l] += x;
                    update(1, 1, n, l, d[l]);
                    if (r < n) {
                        d[r + 1] -= x;
                        update(1, 1, n, r + 1, d[r + 1]);
                    }
                } else {
                    int i;
                    cin >> i;
                    cout << query(1, 1, n, 1, i) << '\n';
                }
            }
        }
        ```

    === "Python"

        ```python
        import sys

        data = list(map(int, sys.stdin.buffer.read().split()))
        n, q = data[0], data[1]
        a = [0] + data[2:2 + n]
        d = [0] * (n + 2)
        for i in range(1, n + 1):
            d[i] = a[i] - a[i - 1]
        t = [0] * (4 * n)
        build(d, 1, 1, n)
        pos, out = 2 + n, []
        for _ in range(q):
            if data[pos] == 1:
                l, r, x = data[pos + 1:pos + 4]
                pos += 4
                d[l] += x
                update(1, 1, n, l, d[l])
                if r < n:
                    d[r + 1] -= x
                    update(1, 1, n, r + 1, d[r + 1])
            else:
                out.append(query(1, 1, n, 1, data[pos + 1]))
                pos += 2
        print("\n".join(map(str, out)))
        ```

    На примере из условия программа печатает `13` и `4`.

## Типичные ошибки

1. **Массив `t` размера $2n$.** Номера вершин доходят почти до $4n$: уже при $n = 6$ есть вершина 13. Бери $4n$.
2. **Перепутаны проверки в `query`.** «Не пересекаются» — `qr < l || r < ql`, «целиком внутри» — `ql <= l && r <= qr`. С перепутанными проверками запрос складывает не те куски; проверь на примере задачи 1 — первый ответ должен быть `20`.
3. **Нет пересчёта на обратном пути.** Без строки `t[v] = t[2 * v] + t[2 * v + 1]` после рекурсии в `update` меняется только лист: в задаче 1 второй запрос снова выведет `20` вместо `14`.
4. **Неверный пустой кусок.** В задаче 2 пустой кусок — $(+\infty, 0)$. С $(0, 0)$ запрос `2 1 4` выведет `0 0` вместо `3 1`: ноль из пустого куска «победит» настоящий минимум.
5. **`int` вместо `long long`.** В задачах 1 и 4 суммы доходят до $10^{14}$ и не помещаются в `int`.
