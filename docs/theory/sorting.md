# Сортировки

**Уровень:** новичок · **Время чтения:** 10 минут · **Теги:** `sortings` · **Проверил:** —

!!! info "Что нужно знать заранее"
    - **C++:** массивы и `vector`, циклы, рекурсия. У кода есть вкладка с Python.
    - **Асимптотика:** что значит «работает за $O(n)$»: при удвоении входа число действий растёт примерно вдвое.

## Зачем это нужно

Дано $n = 2 \cdot 10^5$ чисел, их надо вывести по возрастанию. У пузырька без досрочной остановки $n(n-1)/2 = 19\,999\,900\,000$ сравнений. Для масштаба: $n\log_2 n \approx 3{,}5 \cdot 10^6$. Сортировка за $O(n\log n)$ позволяет обработать такой массив в обычных ограничениях задачи. Это задача 1.

## Идея

Отсортировать массив можно многими способами. Ответ у всех один, а число действий разное:

| Сортировка | Идея | Время |
|---|---|:-:|
| Пузырьком | меняем соседей, пока есть пара не по порядку | $O(n^2)$ |
| Вставками | ставим каждый элемент на своё место в отсортированное начало | $O(n^2)$ |
| Слиянием | сортируем половины по отдельности и сливаем | $O(n \log n)$ |
| `std::sort` | готовая функция из стандартной библиотеки | $O(n \log n)$ |

## Алгоритм

### Пузырьком

Идём по массиву и меняем соседей местами, если левый больше правого. За один проход максимум «всплывает» в конец.

<figure markdown="span">
  ![Один проход пузырька по массиву 4 2 5 1](img/sorting/bubble-light.svg#only-light){ width="374" }
  ![Один проход пузырька по массиву 4 2 5 1](img/sorting/bubble-dark.svg#only-dark){ width="374" }
  <figcaption>Первый проход по 4 2 5 1. Оранжевые — сравниваемые соседи, стрелки крест-накрест — обмен.</figcaption>
</figure>

За второй проход на место встаёт второй по величине, и так далее. Проходов $n - 1$, каждый следующий на одно сравнение короче: в сумме $n(n-1)/2 \approx n^2/2$ сравнений — $O(n^2)$.

### Вставками

Как карты в руке: начало массива уже отсортировано, берём следующий элемент, сдвигаем большие элементы вправо и вставляем его на освободившееся место.

<figure markdown="span">
  ![Сортировка вставками массива 4 2 5 1](img/sorting/insertion-light.svg#only-light){ width="374" }
  ![Сортировка вставками массива 4 2 5 1](img/sorting/insertion-dark.svg#only-dark){ width="374" }
  <figcaption>Зелёные — отсортированное начало, оранжевый — вставляемый элемент, серые стрелки — сдвиг больших вправо.</figcaption>
</figure>

Если массив стоит по убыванию, каждый элемент едет в самое начало — $O(n^2)$. Если массив почти отсортирован, элементы почти не двигаются, и сортировка работает быстро.

### Слиянием

1. Массив из одного элемента уже отсортирован.
2. Иначе делим массив пополам, сортируем каждую половину тем же способом и **сливаем** две отсортированные половины в одну.

<figure markdown="span">
  ![Сортировка слиянием: делим пополам до одиночных элементов, потом сливаем](img/sorting/merge-tree-light.svg#only-light){ width="640" }
  ![Сортировка слиянием: делим пополам до одиночных элементов, потом сливаем](img/sorting/merge-tree-dark.svg#only-dark){ width="640" }
  <figcaption>Сверху вниз делим, пока не останутся одиночные элементы, потом сливаем: пары → четвёрки → весь массив.</figcaption>
</figure>

**Слияние.** Смотрим на первые невзятые элементы обеих половин и забираем меньший. Он не больше всех оставшихся: в каждой половине числа уже стоят по порядку. Когда одна половина кончилась, дописываем остаток другой. Каждый шаг кладёт в ответ один элемент, поэтому половины общей длины $k$ сливаются за $k$ шагов.

<figure markdown="span">
  ![Слияние 2 4 5 7 и 1 3 6 8 по шагам](img/sorting/merge-step-light.svg#only-light){ width="640" }
  ![Слияние 2 4 5 7 и 1 3 6 8 по шагам](img/sorting/merge-step-dark.svg#only-dark){ width="640" }
  <figcaption>Последнее слияние из картинки выше. Зелёный — меньший из двух первых невзятых, он уходит в ответ; оранжевый ждёт; бледные уже забраны. На шаге 8 левая половина кончилась, и 8 просто дописывается.</figcaption>
</figure>

**Почему сортировка верна.** Один элемент уже отсортирован. Если обе половины отсортированы правильно, слияние каждый раз берёт наименьший оставшийся элемент и сохраняет порядок. Повторяя это от одиночных элементов до всего массива, получаем отсортированный массив.

**Сложность.** На каждом уровне обрабатываем суммарно $n$ элементов. Уровней столько, сколько раз можно поделить длину пополам до единицы: $8 \to 4 \to 2 \to 1$ — три деления. Это число обозначают $\log_2 n$; если деление не получается нацело, число уровней округляем вверх. На картинке 3 уровня, по 8 элементов. Итого $O(n \log n)$ времени и $O(n)$ дополнительной памяти на слияние.

### std::sort

Готовая сортировка из `<algorithm>`. Обычно внутри смесь быстрой, пирамидальной сортировки и сортировки вставками; стандарт C++ гарантирует $O(n \log n)$ сравнений. В Python `list.sort()` и `sorted()` — это Timsort, смесь слияния и вставок, тоже $O(n \log n)$.

!!! success "Итог"
    Для обычной сортировки в задачах используй `std::sort` (в Python — `sort` и `sorted`). Пузырёк и вставки нужны здесь для понимания. Идея слияния пригодится и в других алгоритмах, но писать свою сортировку для задачи 1 не нужно.

## Код

=== "C++"

    ```cpp
    sort(a.begin(), a.end());                  // vector по возрастанию
    sort(a.begin(), a.end(), greater<int>());  // по убыванию
    sort(b, b + n);                            // обычный массив int b[n]
    ```

=== "Python"

    ```python
    a.sort()              # по возрастанию
    a.sort(reverse=True)  # по убыванию
    c = sorted(a)         # новый отсортированный список, a не меняется
    ```

Пары (`pair` в C++, кортежи в Python) сортируются по первому элементу, при равенстве — по второму.

## Задача

### Задача 1. Сортировка массива

#### Условие

Дано $n$ целых чисел $a_1, a_2, \ldots, a_n$. Выведите их в порядке неубывания.

**Вход:** в первой строке $n$ ($1 \le n \le 2 \cdot 10^5$), во второй — $a_1, \ldots, a_n$ ($|a_i| \le 10^9$).

**Выход:** $n$ чисел через пробел — отсортированный массив.

<div class="grid" markdown>

```text title="Ввод"
8
5 2 4 7 1 3 8 6
```

```text title="Вывод"
1 2 3 4 5 6 7 8
```

</div>

#### Идея

Сортировки за $O(n^2)$ при $n = 2 \cdot 10^5$ делают порядка $10^{10}$ действий и не успевают. Нужна сортировка за $O(n \log n)$ — берём `std::sort`.

#### Решение

| Шаг рецепта | В этой задаче |
|---|---|
| **Что храним** | все $n$ чисел в массиве |
| **Действие** | сортируем весь массив по неубыванию |
| **Ответ** | выводим элементы по порядку |

**Доказательство.**

- **База.** После чтения массив содержит ровно числа из условия.
- **Переход.** Сортировка переставляет элементы по неубыванию, не меняя их значения и количество. Вывод каждого элемента слева направо даёт требуемый ответ.

**Сложность.** $O(n \log n)$ времени, $O(n)$ памяти на массив; в эту оценку помещается и дополнительная память библиотечной сортировки.

=== "C++"

    ```cpp
    #include <algorithm>
    #include <iostream>
    #include <vector>
    using namespace std;

    int main() {
        ios::sync_with_stdio(false);
        cin.tie(nullptr);
        int n;
        cin >> n;
        vector<int> a(n);
        for (int &x : a) cin >> x;
        sort(a.begin(), a.end());
        for (int i = 0; i < n; i++) cout << a[i] << (i + 1 < n ? ' ' : '\n');
    }
    ```

=== "Python"

    ```python
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()
    print(*a)
    ```

На примере из условия программа печатает `1 2 3 4 5 6 7 8`.

## Типичные ошибки

1. **Сортируется не тот кусок.** Если массив хранится с индекса 1, нужно `sort(a + 1, a + n + 1)`; а `sort(a, a + n - 1)` не трогает последний элемент. Как заметить: в задаче 1 поставь самое маленькое число последним.
2. **`<=` в своём компараторе.** Для чисел компаратор должен задавать строгий порядок: `a < b`, а не `a <= b`. В частности, для равных элементов он должен вернуть `false`. Нарушение требований даёт неопределённое поведение: сортировка может упасть или выдать неверный результат. Как заметить: проверь тест, где все числа равны.
3. **Своя сортировка за $O(n^2)$.** Пузырёк при $n = 2 \cdot 10^5$ делает почти 20 миллиардов сравнений — см. раздел «Зачем это нужно». Как заметить: проверь максимальный массив в обратном порядке.
4. **Строки вместо чисел в Python.** `sorted(input().split())` сравнивает строки, и `"10"` оказывается раньше `"9"`. Как заметить: в задаче 1 подай на вход `9 10` — должно остаться `9 10`.
