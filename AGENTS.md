# Олимпиадная база — открытая Теория и Практика для подготовки к олимпиадам по программированию

Цель: качественная база Теории и Практики для олимпиадников + вход по хендлу Codeforces и стартовая статистика из Codeforces API. Качество важнее количества: лучше 8 отличных статей, чем 30 средних.

## Стек
- Сайт: MkDocs Material, весь контент — Markdown в `docs/`.
- Статистика: `docs/me.md` + `docs/js/progress.js` — браузер ходит в Codeforces API напрямую (user.info, user.status). Без бэкенда, без паролей.
- Запуск: `python -m mkdocs serve`. Проверка: `python scripts/check.py`.

## Где что лежит
- `docs/theory/<slug>.md` — статьи, строго по `docs/STYLE.md`.
- `docs/practice/<slug>.md` — подборки задач: ссылки, сложность, подсказка без спойлера.
- `docs/assets/topics.json` — список тем: slug, название, уровень, теги Codeforces, hook (задача для раздела «Зачем»), reviewed_by.
- `scripts/check.py` — проверки: ссылки на Codeforces существуют (по problemset.problems), у статей есть все разделы, сборка проходит.
- `docs/INCIDENTS.md` — журнал ошибок ИИ: время | что случилось | кто поймал | какое правило ввели.
- `docs/CONTEXT.md` — решения и контекст хакатона. Читать, только если задача про продукт, объём или питч.

## Правила
- Делай только то, что в задаче. Не добавляй страницы, функции и зависимости без просьбы.
- Не выдумывай задачи и ссылки. Задачу Codeforces бери только из `data/cf_problems.json` или из списка, который дал человек. Не уверен — пиши «ссылка не найдена» и оставь человеку.
- Код в статьях рабочий: прогони его на примере из статьи и вставь вывод в отчёт.
- Статья — строго по `docs/STYLE.md`. Если в `docs/theory/` есть статья с «Проверил: <имя>», она — образец тона и глубины.
- Поле «Проверил» заполняет только человек.
- Перед push: `python scripts/check.py` и `python -m mkdocs build --strict`. RED — не пушить.
- Коммить только свои файлы: `git add <пути>`, не `git add .`. Сообщение: `<тема или часть>: что сделано`, после пустой строки трейлер `Agent: <модель>`.
- Запрещено: `git push --force`, `git reset --hard`.
- Отчёт в конце: ИЗМЕНИЛ / ПРОВЕРИЛ (вывод команд) / НЕ ПРОВЕРЕНО / ВОПРОСЫ ЧЕЛОВЕКУ.
- Две неудачные попытки подряд — остановись и опиши проблему, третью наугад не делай.
